# SL Engine Truth Lock

## Identity

**SL Engine** means **Seductive Lust Engine**. It is Cairo's bounded agentic intelligence membrane inside Project Jennifer.

The engine does not treat a general-purpose model as sovereign. The model is an inference substrate operating inside Cairo's corpus, identity and KPGS boundaries.

## Canonical execution order

```text
Player / world event
      ↓
Input normalization
      ↓
Seduction retrieval
      +
Kama retrieval
      +
Rhythm selection
      ↓
3-of-3 canonical gate
      ↓
CDP: generate bounded possibilities
      ↓
CCP: converge on a candidate
      ↓
Cairo identity check
      ↓
Model realization
      ↓
KPGS validation
      ↓
Dialogue / action / refusal
      ↓
Receipt + telemetry
```

No downstream model prompt may silently bypass the 3-of-3 canonical gate.

## Model boundary

Phase 0 recommends a lightweight small language model such as **Microsoft Phi-4-mini-instruct** for the first Azure proof. This recommendation is not a permanent model lock.

The model may be replaced without changing Cairo's canonical identity if the replacement still satisfies:

- small / economical deployment profile;
- structured-output support;
- deterministic-enough evaluation;
- private corpus grounding;
- KPGS-governed execution;
- receipt generation.

## RAG before fine-tuning

Initial implementation is retrieval-first:

```text
SL Engine v0 = SLM + three-vector retrieval + Cairo identity + KPGS
```

Fine-tuning is a later gate. Validated player interactions may eventually become supervised examples, but no training run is canonical until its data lineage, evaluation and rollback path are recorded.

## First environment

The first Cairo test environment is the **Third Signal Chamber**.

It contains:

- one player;
- one Cairo instance;
- three-vector retrieval;
- bounded dialogue;
- receipt logging;
- no autonomous faction control;
- no unrestricted world mutation.

## Success criterion

Phase 0 becomes Phase 1 only when a test can prove:

1. all three vectors were consulted;
2. retrieved evidence is provenance-linked;
3. CDP and CCP stages are visible in machine-readable telemetry;
4. KPGS produces a verdict;
5. the final response is traceable to the receipt.
