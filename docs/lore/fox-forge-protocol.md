# Fox Forge Protocol [FFP]

**Status:** governed POC / visual + runtime vocabulary  
**Project:** Project Jennifer  
**Law:** *same identity, many embodiments; a render may suggest, but only a receipt may promote.*

## Purpose

FFP turns animal-form symbolism into a governed Project Jennifer subsystem instead of aesthetic drift.

It extends existing Project Jennifer companion architecture without collapsing:

```text
identity × edition × rarity × form × mechanism × relationship × skills × history
```

An animal form is one governed dimension of embodiment. It does not silently rewrite identity, relationship state, morality, mechanism or world history.

## Scene modes

FFP defines four presentation modes:

- `work` — building, coding, learning, research and execution;
- `cloud` — imaginative digital-companion/dream-space presentation;
- `healing` — calm restorative reflection without medicalising the player;
- `mission` — field execution, quest movement and high-agency action.

A scene mode may change presentation. It may **not** change identity canon.

```text
scene mode
→ lighting / pose / environment / UI / effects

scene mode
✕ identity
✕ pronouns
✕ animal-form canon
✕ relationship truth
✕ world history
```

## Digital Princess Engineering: rules + learning

The TensorFlow learning lane introduces an important architectural split.

Traditional deterministic programming:

```text
RULES + DATA → ANSWER
```

Supervised machine learning:

```text
DATA + LABELS → LEARNED PATTERN
```

Project Jennifer needs both, but they have different authority.

```text
                     PROJECT JENNIFER
                            │
              ┌─────────────┴─────────────┐
              │                           │
      GOVERNED / RULE LOGIC        LEARNED / ML LOGIC
      deterministic                probabilistic
              │                           │
      identity canon               activity recognition
      permissions                  context classification
      source authority             scene-mode suggestion
      receipts                     pattern detection
      FFP invariants               prediction
              │                           │
              └─────────────┬─────────────┘
                            ▼
                    VALIDATION GATE
                            ▼
                     PRESENTATION
```

### Governing law

> **Do not machine-learn what must be governed. Do not hand-code everything that must be inferred.**

A model may predict that `mission` mode currently fits with 0.88 confidence. It may not decide that Forge is no longer a fox or that Jennifer has acquired an animal form.

The runtime boundary is encoded in `packages/shared/src/fox-forge-protocol.ts`.

## Asset governance

Generated visual material is registered under:

`assets/Fox-Forge-Protocol/source-manifest.json`

Until a binary is actually present, dimension-checked and checksum-pinned, the entry remains `PENDING_BINARY_INTAKE`.

A generated poster is never allowed to outrank machine canon merely because text appeared inside the image.

## Namespace boundary

FFP extends existing systems; it does not replace them:

- **Project Waifu Forge** — current/tested relational engineering, visual sources, constructs and receipts;
- **Project Wify Jennifer** — Genesis / Convergence lore and world-governance mythology;
- **FFP** — governed animal-form and scene-presentation vocabulary.

RIVM remains responsible for consequential relationship-bearing inference. FFP does not infer relationship truth from visual intimacy.

## Proof boundary

Current FFP POC proves:

- explicit machine canon exists;
- scene modes are typed and bounded;
- learned scene predictions can be gated without canon mutation;
- unassigned identities remain unassigned;
- visual derivatives have a manifest and pending-binary state.

It does **not** yet prove:

- a TensorFlow model is production-trained;
- scene prediction is wired into the live game;
- generated PNGs have been binary-admitted;
- Jennifer/Kairo/clan animal forms exist;
- scene switching is narratively validated with players.
