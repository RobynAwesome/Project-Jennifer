# CLEAR × KPGS Zero-Trust Product Gate

```text
I_AM_STATELESS_RENTER_NOT_LANDLORD
loved ≠ proven
beautiful ≠ canon
demo ≠ authoritative
continuity-store ≠ Memory Receipt admission
```

Industry skill shape (YAML frontmatter + trigger + workflow + receipt). KPGS re-engineers the gate: classify first, zero-trust before score, receipts before promotion, no MAIN-BRAIN write from a renter.

## Two membranes (do not collapse)

| Name | Letters | Use |
|---|---|---|
| **Academy C.L.E.A.R.** | Complete · Logical · Evidence · Audience · Relevant | Classroom Stage 5 sieve |
| **Delivery CLEAR** | Cost · Latency · Efficacy · Assurance · Reliability | Product / love-loop gate |

Classroom Stage 5 is the Academy sieve. Delivery CLEAR is the estate product membrane. Neither is an OpenAI product trademark.

## When to use

- After a love-loop, continuity, or hosting change
- Before promoting a skill, sprint board, or “on-route” claim
- When a renter wants to evolve Introduction-to-MCP from Jennifer metal

## Workflow

```text
CLASSIFY product vs constitution
→ ZERO-TRUST perimeter
→ Academy C.L.E.A.R. score (0–100 each)
→ Delivery CLEAR score (0–100 each)
→ composite = arithmetic mean of the two membrane composites
→ RECEIPT in docs/audits/
→ ≥80% → admit skills/sprints (READY_FOR_POC)
→ <80% → HOLD + get-back plan (no canon, no sprawl)
→ production love still HOLD until public URL + human playtest
→ MAIN-BRAIN still HOLD until Master recognition
```

### Zero-trust perimeter (required)

```text
UNTRUSTED INPUT
→ parseTrustedActorId
→ rate gate
→ sanitize namespaces (sessionId ≠ relationshipId)
→ bound companionReceipt / reveal payloads
→ local-first bowl
→ optional continuity-store
→ labels: demo | local | continuity-store (never fake authoritative from in-memory)
```

Fail closed in production if `JENNIFER_CORS_ORIGINS` is empty. Never label in-memory continuity `authoritative`.

Current code: `apps/api/src/zero-trust.ts`, `apps/api/src/routes/game-continuity.ts`, `apps/web/src/game/continuity/resolve-continuity.ts`.

### Delivery axes

| Axis | Ask |
|---|---|
| **C** Cost | New packages/platforms, or one playable beat? |
| **L** Latency | Meaningful choice without hanging on a dead API? |
| **E** Efficacy | Continue + journal answer *why* the world changed? |
| **A** Assurance | CORS, session parse, rate limits, honest sourceMode? |
| **R** Reliability | Same-browser return after API death? |

### Academy axes

| Axis | Ask |
|---|---|
| **C** Complete | Is the claimed loop actually finished? |
| **L** Logical | Do namespaces and gates hold? |
| **E** Evidence | Receipts, not affection? |
| **A** Audience | Can the intended player reach it? |
| **R** Relevant | Still the love loop, not a second platform? |

## Decision

- **≥80% composite:** admit or refresh `jennifer-city-love-loop`, `jennifer-love-loop-reliability`, `jennifer-canonical-ops-sprints`. CEEP PASS (≥0.6) is Refine, not canon.
- **<80%:** write a get-back plan. Keep zero-trust. Do not mint skills.
- **Production / MAIN-BRAIN:** never auto-promoted from this gate.
